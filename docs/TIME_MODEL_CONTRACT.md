# R1 時間モデル・処理契約

状態: R1設計。以下は正規版の意味契約・検証基準であり、実用DSP、リアルタイム性能、聴感の受入済み宣言ではない。上位要求は [SPECIFICATION.md](SPECIFICATION.md)。実験方式・性能上限は測定して決定する。

## T1 座標と状態所有

全ての離散座標は共通処理サンプルレート Fs のサンプル単位で表す。異レート素材は明示した変換経路を経て使用し、元のレート・長さも保持。秒表示は frame/Fs、符号付き配置の整数化は最近接フレーム（同距離なら絶対値の大きい方）。速度は無次元の符号付き倍率。負の座標は配置として有効。上限は実際の共有部品・メモリ・計算能力を表示し、別repoの数値を根拠なく転用しない。

- n: 単調増加する出力フレーム。音声停止中は音響時間を進めない。出力デバイス時刻とは区別する。
- S(n): 原素材の参照座標（Source Time）。原音レンダラーが q[n] を生成する。素材座標と入力が励振された時刻 e を区別。
- A(n): Integrated用の残響経過時計。速度 v は A(n+1)-A(n)。seekはその境界での変位、原音やWetの時刻を書き換えない。IR Spectral/WindowのIR Timeは直接参照するカーネル位置であり、IntegratedのAとは意味を分ける。
- W(n): 構築済みWetの参照座標（Wet Time）。各出力時刻に対する表示位置と実際に適用された位置を区別。
- 位相: 再合成器が持つ内部状態。時間参照の速度・方向と独立し得る。rawモードは参照波形を直接読む。continuousモードは局所状態を再合成するため位相履歴を保持する。
- UIは各軸の要求値を所有し、エンジンは適用値と世代を返す。古い非同期結果が最新要求を上書きしてはならない。停止、seek、freeze、ループ、方向変更、モード変更、素材差替え時の状態を別々に扱う。

参照速度0は参照位置の固定であり、出力クロック停止でも無音化でもない。rawの一点固定はDCになるため、聴取用Buffer Freezeは局所波形ループ、continuous Freezeは非DCの再合成。raw数学参照と聴取用の違いを隠さない。

## T2 線形基準・符号付き配置

有限入力 x[0..N-1]、IR h[0..M-1]、整数配置 d を用い、範囲外は0とする。

通常 Wet: y[n] = Σ_e x[e] h[n-e-d]。配置範囲 [d,d+N+M-1)。インパルス入力・d=0ではIR原波形に一致する。
逆方向 Wet: y_rev[n] = Σ_e x[e] h[e+d-n]。配置範囲 [d-(M-1),d+N)。すなわち逆順IRを置き、終端を入力の e+d に合わせる。dは進行方向と独立。
d<0または逆方向に必要な未来入力は、有限素材の先読み・キャッシュで取得する。ライブ相当の入力で未知の未来や未来の操作を予知したと扱わない。不足範囲は未準備／実際の先読み遅延として明示する。

DryとWetは共通の符号付き座標に配置し、有限比較範囲 [L,R) を両者の支持区間の和集合を覆う区間として選ぶ。共通座標反転は n→L+R-1-n を両者に適用する。これは通常の合成波形の完全逆再生。原音を維持した逆順IRとは別。個々のバッファを各自の長さで反転して位置をずらさない。

基準畳み込みはIRの自動正規化をしない。IR共通校正（選択可能）とDry/Wet・出力Gain・安全段は独立。Wet/Dryは0でDryのみ、1でWetのみ。Dryモードの基準原音はMixで減衰させない。比較ソロは明示的に切り替える。安全処理前の線形基準を数値試験し、安全処理後の上限・クリック・聴感は別試験。

チャンネル対応の初期契約: mono→mono、mono×stereo IR→stereo、stereo×mono IR→stereo、stereo×stereo IR→同側の独立畳み込み。4ch true-stereoの交差行列やその他の多chは未対応を明示し、黙ってmono化しない。比較素材のチャンネル変換を同一条件にする。

## T3 Integrated: 寄与の経過時間を操作する

q[e] を時刻eの実入力（Source Timeから生成したPCM、ミックス済み）とし、配置 p=e+d とする。各寄与は p に開始し、そのときの時計 A(p) をアンカーとして保持する。開始後の経過参照は a(n,e)=A(n)-A(p)。通常 A(n)=n のとき a=n-e-d。

raw参照の数学基準（有限履歴）:
y[n] = Σ_{e: p≤n} q[e] h(a(n,e))。
これにより速度変更は既存寄与のageを連続的に進め、seekは既存寄与に共通変位を与える。seek後の新規入力はその時点をアンカーとしてage=0で開始する。同じIR断面を全入力に無条件適用しない。A(n)を止めてもnは進み、後続入力は新規寄与として扱う。qの供給停止後も保持済み寄与は再参照可能。原音再生停止と全音声停止は区別する。

IntegratedのIR Positionは基準励振（選択可能な保持履歴の配置p_ref）に対するage A(n)-A(p_ref) を示し、seekは共通時計に差分を加える。他の寄与のageは一般に異なる。基準がないときは未設定とし、単一の実IR参照位置で全寄与を代表したふりをしない。

IR Range [l,r) の範囲外は非ループでは0。repeatは l+mod(a-l,r-l)。pingpongは端のサンプルl,r-1間を反射し、幅1はl固定。raw整数位置は厳密、非整数は隣接サンプル補間（repeatの末尾は先頭へ）。ループ境界・seekの聴感上のクリック対策は別の明示的な遷移処理とする。Aは非単調も許容する。

continuous位相モードでは h(a) の代わりに、各寄与の局所IR状態を出力時刻で再合成する。振動速度を維持する局所窓／STFTの近似であり、物理音場の停止ではない。位相状態を無条件に全寄与で共有すると干渉が変わるため、同値な群化・効率化は小規模寄与別参照との比較で検証。Aの固定時にraw参照は一定値になり得るが、continuousでは局所の非DC成分を持続させる。通常raw条件では基準畳み込みに数値一致。逆方向畳み込みはT2の配置、既存残響の巻き戻しはAの逆行として区別する。

有限履歴境界: 保持済みq、アンカー、時計／操作履歴、IR版、位相状態、再計算可能なキャッシュ範囲を明示。配置時刻の記録がない寄与を推定で復元しない。入力・IR差替えは世代を更新し、旧計算結果を拒否。保持外参照は未準備として伝え、利用可能な音・制御は維持。固定の連続励振は寄与を蓄積し得るため有限の保持・出力安全制御を検証し、無限の物理残響と称さない。

## T4 8モードの意味

| モード | Wetの構築 | 時間・位相 |
|---|---|---|
| Dry | なし | Sourceのみ |
| Normal Convolution | T2通常 | Sourceに追従する基準 |
| Reverse Convolution | T2逆方向 | Sourceを維持、未来入力の準備 |
| Wet Buffer Scrub | 通常Wetの有限キャッシュ | Wを直接参照、0速は局所ループ |
| Wet Spectral Scrub | 通常Wetの有限キャッシュを分析 | Wと局所位相を分離 |
| IR Window Scrub | 選択IR窓を時刻0に再配置して畳み込む | IR位置を変える。既存Wet巻戻しではない |
| IR Spectral Remapping | IR局所状態を有限カーネルへ再合成して畳み込む | IR参照の軌道と位相を分離。既存寄与のage変更ではない |
| Integrated Remapping | T3の寄与別age操作 | S・A・Wを独立。Wは構築済み部分を参照する後段。通常条件は直結 |

利用できる軸と、効果を持たない軸はモードごとに明示。共通設定を維持してA/B。全体逆再生は共通有限座標のraw反転を利用し、9番目の方式を追加しない。すべての操作を同じ内部キャッシュ方式に強制しない。

## T5 検証基準と実装境界

- E1: 小規模Float64直接和oracleと比較。整数配置、負配置、インパルス、通常／逆方向、異長Dry/Wetの共通座標反転、単純Delay。比較対象は安全段前の有限波形・座標。Float32実装は有限テストで max(abs(error)) ≤ 1e-6 × max(1, peak(reference)) を初期受入値とする。長いIRのFFT等で変更が必要な場合は誤差・規模・根拠を測定して記録する（ユーザー指定の固定値ではない）。
- E2: 独立時計、複数励振、速度0・seek・逆行・新規励振アンカー、保持範囲・loop/pingpongを試験。raw oracleは独立した小規模比較実装であり本番の寄与全展開を要求しない。
- E3: continuousはSTFT位相・ステレオ・非DC維持、定常トーンの周波数、減衰包絡、窓移動・遷移を測定。ゼロ速度、低／高速、逆行、往復と、波形のraw反転の差を比較。音響品質の許容域はR3〜R5の測定で決める。
- E4: 共通キャッシュ、旧世代拒否、非対応明示、出力安全、独立操作、A/B、可視化の実データ一致を自動／実ブラウザ検証。聴感と物理端末検証は別に記録し、未検証を完了としない。

R1のoracle: tests/helpers/time-reference.mjs、tests/time-contract.test.mjs。productionはR2以降、既存ATF/FWの固定版を利用して設計。R1では具体的なFFT方式、ウィンドウ長、メモリ上限、性能保証は確定しない。
